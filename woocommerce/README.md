# woocommerce

Skills for **WooCommerce core and the WooCommerce extension family** — WC itself, plus official extensions like Subscriptions, Memberships, the Stripe gateway, etc.

Use these when extending Woo or building an integration that touches Woo data.

## WooCommerce core

| Skill | Purpose |

Corrects the "this is React, removing fields is hard" misconception — the zone-method modal is Backbone, field list is fully PHP-controlled. |

| `wc-variations-pricing-filters` | Mutate variation prices via filters — pick the right layer (`woocommerce_product_get_price` vs `woocommerce_product_variation_get_price` vs the `woocommerce_variation_prices_*` aggregation family), and CRITICAL: filter `woocommerce_get_variation_prices_hash` whenever your logic depends on context outside the default cache key. | `wc-rest-api-v4` | Audit WooCommerce's source-gated `wc/v4` API — Woo 11.0 ships controller code but keeps the core namespace disabled in the release build. Covers exact route discovery, v3 fallback, latent refund preview/settings/fulfillment routes, permissions, hook names, and why `Internal\` controllers are not extension bases. |
| `wc-payment-gateway` | Register a custom payment gateway — extend `WC_Payment_Gateway`, implement `process_payment` returning `array(result, redirect)`, optional `process_refund`, declare features in `$supports`, register via `woocommerce_payment_gateways`. The `payment_complete` vs `update_status` distinction (canonical paid-order state machine vs status-only flip) and the always-forgotten `WC()->cart->empty_cart()` after success. Webhook receiver via `wc-api`. |
| `wc-checkout-block-payment-method` | Build or audit a Checkout **Block** payment-method integration — the four separate layers (`WC_Payment_Gateway` server behavior, the `AbstractPaymentMethodType` PHP adapter, the JS `registerPaymentMethod()` UI, and Store API processing), one stable gateway identifier across all of them, `onPaymentSetup` (not the deprecated `onPaymentProcessing`), returning `paymentMethodData` to bridge legacy `process_payment()` vs owning processing through `woocommerce_rest_checkout_process_payment_with_context` (`PaymentContext` / `PaymentResult`), saved-token UI, client-secret/SDK confirmation, and a classic-vs-Block test matrix. | `wc-emails-classic` | Add/customize classic transactional emails with `WC_Email` — registration, template overrides, locale and guarded send outcomes, HPOS-safe data, Woo 11 pending→cancelled dispatch, backorder-email suppression, and preview-only shipping controls. |
| `wc-coupon-dynamic` | Synthesize **virtual** WC coupons at runtime via `woocommerce_get_shop_coupon_data` — no `shop_coupon` post needed. | `wc-cart-checkout-classic` | Customize the classic (shortcode) cart and checkout — `woocommerce_add_cart_item_data` / `woocommerce_get_item_data` cart-key merging, `woocommerce_before_calculate_totals` absolute price mutation, `woocommerce_cart_calculate_fees`, `woocommerce_checkout_fields`, `woocommerce_after_checkout_validation`, order-line meta vs order meta, HPOS-safe order saves, and the Checkout Block / Store API boundary. | `wc-store-api` | Build shopper-facing headless/cart/checkout integrations under `/wc/store/v1` — Nonce versus Cart-Token, CORS/sessions, endpoint extensions, additional checkout fields, payment requirements, Woo 11 collection-count bounds, decoded-JSON handling, validate-before-persist checkout, and private-parent variation/review disclosure guards. |
