# learndash

Integration and audit skills for **[LearnDash LMS](https://www.learndash.com/)** (`sfwd-lms`) and the **LearnDash WooCommerce** bridge (`learndash-woocommerce`) — the enrollment, group, and headless surfaces a crossover plugin, theme, import, or CRM/checkout bridge has to get right.

These are skills for making **your own** code cooperate with LearnDash, not for re-implementing it. LearnDash already owns the access decision (`sfwd_lms_has_access()`), the user/course/group/leader relationship model, course-step structure, learner progress/activity synchronization, the WooCommerce access counter, and the REST controllers under `ldlms/v2` — a crossover plugin should use the public access and progress helpers rather than writing LearnDash usermeta or activity tables by hand. The running theme across the batch: **course access is not course progress**, **grant/revoke through the LearnDash helpers** so activity records, historical `enrolled_at` timestamps, transients, and hooks stay coordinated, and **respect the WooCommerce bridge's model** — product/variation `_related_course` / `_related_group` relations, configurable grant/revoke statuses, partial refunds, subscription switches, HPOS-safe order CRUD, the silent enrollment queue, and the per-user access counter that stops one order from revoking access another still grants. Verified against LearnDash LMS 5.1.9 and LearnDash WooCommerce 2.0.2 local source.

## Skills

| Skill | Purpose |
|---|---|
| `learndash-course-access` | Course access and enrollment: `sfwd_lms_has_access()` as the canonical gate and its full decision chain (direct/group/open/sample/auto-enroll/free-paynow, start-end window, expiration), granting/revoking through `ld_update_course_access()` and the `Product` model (not raw usermeta), `ld_course_access_from_update()` for historical access dates, the read APIs (`ld_course_access_from`, `ld_course_access_expires_on`, `learndash_user_get_enrolled_courses`, `learndash_get_users_for_course`), the forced-`$bypass_transient` and open-course query caveats, and the course-steps outline APIs (course structure is not access). |
| `learndash-course-progress` | Learner progress and completion lifecycle: safe summary/status reads, completion-order navigation, single and bulk progress writes, force and shared-step boundaries, lesson/topic/quiz/course hooks, incomplete/reset behavior, activity synchronization, challenge-exam reset, the 5.1.8 `previous_incomplete_step` contract, and the read-only REST progress boundary. |
| `learndash-group-access` | Group membership and group-driven course access: the three separate relationships (user → group, group → course, leader → group), the correct helpers (`ld_update_group_access`, `ld_update_course_group_access`, `ld_update_leader_group_access`, the `learndash_set_*` diff helpers), where each meta lives, hierarchical-group expansion, and the 5.1.8+ union of explicit membership with Managed Groups auto-enrollment. |
| `learndash-woocommerce-access` | The LearnDash WooCommerce bridge that grants/revokes access from Woo products, orders, refunds, subscriptions, switches, and order-item changes: the `_related_course` / `_related_group` product/variation relation model, the configurable grant/revoke `learndash_woocommerce_enrollment_status_settings`, partial-refund and subscription lifecycle handling, HPOS-safe order CRUD, the `learndash_woocommerce_silent_course_enrollment_queue`, and the per-user `_learndash_woocommerce_enrolled_courses_access_counter` that prevents one order/refund from revoking access another still grants. |
| `learndash-rest-api` | REST / headless integrations: `ldlms/v2` data/relations plus `learndash/v1` manifest/OpenAPI discovery, enablement and customizable bases, the nested ID-keyed `/steps` body, enrollment/relation permissions, 5.1.7+ course pagination normalization, the read-only user-progress routes, and safe extension through explicit permission callbacks. |
